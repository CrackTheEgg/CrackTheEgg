Mock Client Brief

Project: Secure Contact Form • Date: 2025‑08‑12

Objective: Enable visitors to send secure messages without storing personal data, ensuring high deliverability and minimal spam.

Functional Requirements

  • Secure web‑to‑email / web‑to‑SMS pipeline (no persistent PII)
  • Spam prevention: honeypot, bot detection, throttling
  • TLS end‑to‑end; CORS restricted to https://christianhegarty.com
  • Logging & monitoring for failures and API usage
  • Low‑cost, serverless‑first approach
  • Record engagement metrics in CloudWatch (total, by reply type)

Security Requirements

  • Validate email and E.164 phone numbers
  • Honeypot field + render‑time token with minimum submission delay
  • Least‑privilege IAM; no PII in logs

Constraints

  • Integrates with Chapter 2 static site (S3 + CloudFront)
  • AWS‑native services preferred
  • Minimal operational overhead

Out of Scope

  • Persistent storage of submissions
  • Advanced analytics or DynamoDB integration

Solution Response

Services: S3 + CloudFront (frontend), API Gateway (Regional), Lambda (Python), SES (email), SNS (SMS optional), CloudWatch (logs, metrics, dashboards).

Flow: Browser → CloudFront → API Gateway → Lambda → SES/SNS; Lambda emits custom CloudWatch metrics. No PII persists after processing.

Trade‑offs

  • SES vs third‑party: Lower latency and cost; single‑provider ops.
  • No DB now: Simpler, cheaper; history deferred to a later chapter.
  • Serverless only: Auto‑scales; fewer ops tasks; pay‑per‑use.

Ops & Monitoring

  • CloudWatch alarms: Lambda Errors > 0 (5m), API 5XX spike, SES bounce rate > 5% (1d)
  • Dashboard: invocations, duration p95, 4XX/5XX, bounces, throttles
  • Runbook: investigate alarms → check WAF (if enabled) → API logs → Lambda logs; verify SES DKIM/SPF
